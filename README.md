# LossProof (рабочее название)

Статический сайт (обычные HTML/CSS/JS, без сборки) для сравнения крипто-
маршрутов вывода выплат (биржа для покупки USDT + off-ramp сервис для
конвертации в рубли/локальную валюту) для трейдеров пропфирм из России и
СНГ. Банковский перевод оставлен как контрастный "худший" вариант.

Собран по [payout-comparison-site-spec.md](payout-comparison-site-spec.md)
(v1) и [payout-comparison-site-spec-v2-crypto-pivot.md](payout-comparison-site-spec-v2-crypto-pivot.md)
(v2 — пивот с Wise/Revolut/банка на крипто-маршруты, потому что Wise и
Revolut не работают с резидентами России из-за санкций).

## Запуск локально

Node.js/Python не требуются. В `scripts/serve.ps1` лежит небольшой
статический сервер на PowerShell (использует `System.Net.HttpListener`,
ничего устанавливать не нужно):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\serve.ps1
```

Затем откройте http://localhost:8080/. (Открывать HTML-файлы напрямую через
`file://` не получится — страницы используют пути от корня сайта вроде
`/assets/...`, чтобы работать так же, как и после публикации.)

## Публикация

Подойдёт любой статический хостинг «как есть» (сборка не нужна): Netlify,
Vercel, Cloudflare Pages, GitHub Pages. Достаточно указать хостингу на корень
этой папки.

## Структура

Сайт двуязычный: русская версия лежит в корне, английская — в `en/` с тем же
набором страниц (например `/payout/ftmo/` и `/en/payout/ftmo/`). В шапке
каждой страницы есть переключатель языка (иконка 🌐), который ведёт на
соответствующую страницу на другом языке.

- `index.html` / `en/index.html` — главная страница: заголовок-обещание
  («путеводитель в мире трейдинга»), плитка-хаб (`.hub-grid` в
  `style.css`) с карточками-разделами (калькулятор переводов, сравнение
  пропфирм, вывод по фирмам, гид по крипто-выводу, сравнение бирж) и блок
  «Почему LossProof» с перечислением сильных сторон сайта. Виджет
  калькулятора здесь больше не встроен напрямую — только карточка-ссылка на
  `/calculator/`. В шапке этой страницы (и только этой) навигация свёрнута
  до одной ссылки на «Раскрытие информации» — остальные разделы вынесены в
  плитку ниже заголовка; на всех остальных страницах сайта полная навигация
  сохранена.
- `calculator/index.html` / `en/calculator/index.html` — «Калькулятор
  переводов» (URL и код-идентификаторы всё ещё `calculator`/`calc-*` —
  переименовано только то, что видит пользователь): два поля — «Откуда» (у
  конкретной пропфирмы / на карте в любой валюте / уже в крипте, в том
  числе на конкретной бирже) и «Куда» (на конкретную биржу / сравнить все
  биржи / на оплату челленджа у конкретной пропфирмы / в конкретную валюту
  через off-ramp) — свободно комбинируются в любом направлении, а не только
  «пропфирма → валюта». Работает и как калькулятор вывода выплаты, и как
  калькулятор оплаты челленджа криптой (актуально для трейдеров из РФ/СНГ,
  которым карта может не дойти до западного мерчанта напрямую). Подробности
  логики см. в разделе «Как считает виджет» ниже. Блок с гридом всех фирм
  отсюда убран в отдельный раздел — см. `payouts/` ниже; здесь осталась
  только одна ссылка на него.
- `payouts/index.html` / `en/payouts/index.html` — раздел «Вывод по фирмам»:
  список всех пропфирм на сайте (грид из `FIRMS`, тот же компонент
  `.firm-grid`, что и в других местах) со ссылкой на инструкцию по выводу
  для каждой. Раньше кнопка «Вывод по фирмам» в навигации вела на
  `/calculator/#firms` — теперь это отдельная страница с полным списком, не
  привязанная к калькулятору.
- `payout/<slug-фирмы>/index.html` / `en/payout/<slug>/index.html` — страница
  на каждую пропфирму: способы вывода, комиссия, минимальная сумма,
  скорость, встроенный калькулятор переводов (открывается сразу с этой
  фирмой в поле «Откуда» — `presetSource: "firm:<slug>"` в вызове
  `initCalculator`), перекрёстная ссылка на
  `/prop-firms/<slug>/` (если фирма есть в сравнении) и грид «Другие
  инструкции по выводу». Есть страницы для всех 7 фирм в `FIRMS`: ftmo,
  fundednext, the5ers, e8-markets, topstep, brightfunded, blueberry-funded
  — раньше здесь не хватало последних трёх, хотя они уже были в сравнении
  пропфирм (`PROP_FIRMS`) со ссылкой на несуществующую страницу.
- `prop-firms/index.html` / `en/prop-firms/index.html` — раздел «Сравнение
  пропфирм»: фильтруемая и сортируемая карточная сетка (не таблица — 11 полей
  на фирму никогда не влезли бы в контейнер ~1080px без горизонтальной
  прокрутки ни на каком экране, поэтому карточки всегда, не только на
  мобильных) по типу оценки, стоимости входа, профит-сплиту, просадке,
  размеру аккаунта, методу выплат, Trustpilot, broker-backing и году
  основания. Обязательный блок дисклеймера о нерегулируемости индустрии —
  прямо на странице, над карточками.
- `match/index.html` / `en/match/index.html` — раздел «Подбор пропфирмы»:
  квиз из 5 вопросов (рынок, способ вывода, формат оценки, важность
  репутации, бюджет), который взвешенно сравнивает только фирмы из
  `PROP_FIRMS` (не весь рынок) и показывает топ-3 с честной раскладкой,
  какие критерии совпали, а какие нет. В отличие от калькулятора переводов,
  здесь нет ни одной внешней зависимости (курсов, живых тарифов) — вся
  логика детерминирована и считается мгновенно на уже имеющихся данных.
  Единственный жёсткий фильтр — рынок (форекс/фьючерсы, поле `markets` у
  каждой фирмы): Topstep — единственная фьючерсная фирма в сравнении,
  остальные пять — форекс/CFD, поэтому смешивать их в одном скоринге не
  имеет смысла. Всё остальное — взвешенные баллы, поэтому квиз никогда не
  выдаёт пустой результат, даже если идеального совпадения нет (см.
  `assets/js/match.js`).
- `prop-firms/<slug>/index.html` / `en/prop-firms/<slug>/index.html` — страница
  по каждой фирме: ключевые факты, правила оценки, раскрываемая по кнопке
  таблица цен по размерам аккаунта, перекрёстная ссылка на инструкцию по выводу
  (`/payout/<slug>/`, если она есть) и обратно.
- `crypto-payout-guide/index.html` / `en/crypto-payout-guide/index.html` — гид по крипто-маршрутам вывода
- `exchanges/index.html` / `en/exchanges/index.html` — раздел «Сравнение
  бирж»: фильтруемая и сортируемая карточная сетка (та же логика, что у
  сравнения пропфирм — см. ниже) проверенных лицензированных криптобирж по
  лицензиям, доступу для резидентов РФ, комиссии спот-торговли и способам
  пополнения. Только площадки с публично проверяемой лицензией/

- `exchanges/<slug>/index.html` / `en/exchanges/<slug>/index.html` — страница
  по каждой бирже (bybit, bitget, kucoin, okx, mexc, gate): ключевые факты,

  (лицензия, какую крипту принимает, в какие валюты выводит, комиссия,

- `disclosure/index.html` / `en/disclosure/index.html` — раскрытие партнёрской монетизации
- `assets/js/data.js` — редактируемые данные для русской версии: валюты,

  предлагает их и как альтернативу бирже для покупки крипты, но тариф на

  справочные ресурсы (`E_WALLETS`, `REFERENCE_RESOURCES` — не участвуют в

  пропфирм (`FIRMS`), данные для сравнения пропфирм (`PROP_FIRMS` —
  числовые поля для сортировки/фильтрации плюс текстовые для отображения),
  данные для сравнения бирж (`EXCHANGES_COMPARE` — отдельный, более широкий

  выше; чисто информационный раздел, без партнёрского статуса; см.
  комментарий над `EXCHANGES_COMPARE` в файле)
- `assets/js/data.en.js` — то же самое для английской версии. **При смене
  цифр (спред, комиссии, лимиты, slug фирмы) нужно обновить оба файла** —
  тексты можно переводить независимо, но числа должны совпадать.
- `assets/js/rates.js` — актуальные межбанковские курсы через бесплатный
  Frankfurter API (общий для обеих версий)
- `assets/js/prop-firms.js` — виджеты раздела «Сравнение пропфирм», общие для
  RU и EN: `initPropFirmsTable` (карточки с фильтрами, плюс select для
  сортировки + кнопка направления — не клик по заголовку таблицы, у карточек
  нет заголовков) и хелперы страницы фирмы (`renderPropFirmSummary`,
  `renderPropFirmRules`, `renderPropFirmPrices`, `renderOtherPropFirms`).
  Каждое поле карточки — это `<dt title="…">` с кратким пояснением по
  наведению (замена подсказкам на заголовках таблицы, раз заголовков больше
  нет) и `<dd>` со значением. Язык берётся из `<html lang>`, подписи — из
  `PROPFIRMS_STRINGS` внутри файла (как `CALC_STRINGS`).
- `assets/js/match.js` — виджет раздела «Подбор пропфирмы»: `initFirmMatch`
  строит форму из 5 select'ов и на каждый submit (плюс сразу при загрузке,
  с нейтральными значениями по умолчанию) пересчитывает `scoreFirm(firm,
  answers)` для каждой фирмы, чьё поле `markets` совпадает с выбранным
  рынком (единственный жёсткий фильтр). Остальные ответы — взвешенные баллы
  (крипто-выплата ±3/4, формат оценки ±2/3, репутация ±2, бюджет ±2/3) плюс
  список `rows` с пометкой ✓/✗/– на каждый критерий, который и рендерится
  под каждой карточкой результата — чтобы было видно не только итоговый
  скор, но и что конкретно совпало. Топ-3 фирмы по сумме баллов, лучшая —
  с бейджем (стиль `.calc-badge`/`.match-best`, как «выгоднее всего» у
  калькулятора). «Проверенная» фирма (для вопроса про репутацию) —
  `firmIsProven()`: основана до 2019 года ИЛИ Trustpilot 4.5+ при 10 000+
  отзывов; «принимает крипто-выплаты» — `firmHasCrypto()`, проверка
  `payoutMethods` по regex на «крипто»/crypto/USDT/USDC. Никаких внешних
  запросов — детерминированная клиентская логика на данных, которые уже
  используются на `/prop-firms/`.
- `assets/js/exchanges.js` — то же самое для раздела «Сравнение бирж»:
  `initExchangesTable` (карточки с фильтром по доступу для РФ и select для
  сортировки) и хелперы страницы биржи (`renderExchangeSummary`,
  `renderOtherExchanges`). Раздел чисто информационный — партнёрский статус
  биржи там не показывается.
- `assets/js/offramps.js` — виджет раздела «Сравнение обменников»:
  `renderOfframpsCompare` строит карточки прямо из `OFFRAMPS` (тот же
  массив, что считает калькулятор) — отдельного файла данных для этого
  раздела нет. Всего 2 обменника, поэтому без фильтров и сортировки —
  только карточки.
- `assets/js/calculator.js` — виджет «Калькулятор переводов», общий для
  всех страниц (id корневого элемента и функция всё ещё называются
  `calculator-root`/`initCalculator` по историческим причинам). Источник и
  назначение — два независимых поля, оба выбираются свободно (не жёсткая
  пара «пропфирма → валюта»): **откуда** (`source`) — у конкретной
  пропфирмы (`firm:<slug>`, открывает карточку с комиссией/сроками/
  способами вывода этой фирмы из `FIRMS`), на карте в любой валюте
  (`cash:<CUR>`), либо уже в крипте — без привязки к бирже (`crypto`) или
  на конкретной бирже (`crypto:<exchangeId>`); **куда** (`destination`) —
  на конкретную биржу (`crypto:<exchangeId>`), сравнить сразу все варианты
  — биржи И обменники (`crypto:all`), на оплату челленджа у конкретной
  пропфирмы (`firm:<slug>` — берёт `firm.challengePayment` из `FIRMS`) или
  вывести в конкретную валюту через off-ramp (`fiat:<CUR>`). При выборе
  «сравнить все варианты» (для покупки крипты или оплаты фирме) в список
  попадают и `EXCHANGES`, и `OFFRAMPS` с `onRampSupported: true` — вторые
  всегда с бейджем «не подтверждено» (см. комментарий над `OFFRAMPS` в
  `data.js`). Подробности расчёта — в разделе «Как считает виджет» ниже.
  Язык — по атрибуту `<html lang="ru">`/`<html lang="en">`, подписи — из
  `CALC_STRINGS` внутри файла.
- `assets/icons/favicon.svg` — фавикон (растущий график, фирменный градиент
  синий→зелёный). `favicon-16.png`/`favicon-32.png`/`apple-touch-icon.png` —
  растровые версии для браузеров и iOS, подключены на всех страницах через
  `<link rel="icon">`. Чтобы поменять дизайн: отредактируйте `favicon.svg` и
  перегенерируйте PNG — `scripts/upload.ps1` поднимает локальный приёмник
  (`http://localhost:8081`), на который можно POST'ить PNG прямо из
  консоли браузера (canvas → `toBlob` → `fetch`), не гоняя base64 через
  текстовые инструменты.

### Как считает виджет «Калькулятор переводов»

`source` (откуда) и `destination` (куда) — независимые поля вида
`тип:значение` (`parseSource`/`parseDestination` в `calculator.js`
разбирают их на `{type, ...}`), поэтому пары не ограничены направлением
«пропфирма → валюта» — можно точно так же посчитать «карта в рублях →
конкретная биржа», «карта в рублях → оплата челленджа у пропфирмы» или
любую другую комбинацию:

- `source`: `firm:<slug>` (пропфирма — валюта берётся из
  `firm.payoutCurrency`, показывается информационная карточка с выводом),
  `cash:<CUR>` (карта/счёт в любой из `CURRENCIES`), `crypto` (уже в
  USDT/USDC, без привязки к бирже) или `crypto:<exchangeId>` (уже на
  конкретной бирже).
- `destination`: `crypto:<exchangeId>` (конкретная биржа), `crypto:all`
  (сравнить все биржи из `EXCHANGES`), `firm:<slug>` (оплатить челлендж
  этой пропфирмы криптой — берёт `firm.challengePayment` из `FIRMS`) или
  `fiat:<CUR>` (вывести в валюту через off-ramp).

Все комиссии в данных (`EXCHANGES`/`OFFRAMPS`/`BANK_BASELINE`) заданы в
долларах, поэтому расчёт всегда идёт через доллар как опорную точку:
сумма сначала переводится в USD-эквивалент через `getMidMarketRate(from,
"USD")`, если исходная валюта не USD и не крипта (`rateToUSD`), с неё
вычитаются комиссии и применяется спред, а результат переводится в валюту
назначения через `getMidMarketRate("USD", to)`, если это не USD и не
крипта/пропфирма (`rateFromUSD`). Это принципиально: раньше курс
запрашивался только для пары «funding-валюта → local-валюта» напрямую и
никогда не пересчитывался, если направление было «в крипту» — из-за этого
маршрут вида «рубли на карте → купить USDT на Bybit» до этой переделки
считался неверно (курс молча принимался за 1, то есть 100 000 ₽
отображались как ~99 700 USDT вместо реальных ~1 180 USDT).

`runCalculation` дальше ветвится по типам `source`/`destination`
(`isDestCryptoLike = isDestCrypto || isDestFirm` — обе ветки заканчиваются
в USDT, без второго/off-ramp этапа):

1. **`destination` — пропфирма, которая не принимает крипту**
   (`firm.challengePayment.acceptsCrypto === false`, сейчас это только
   Topstep): маршрута нет — сразу показывается предупреждение с честным
   объяснением (какой способ оплаты у фирмы принят на самом деле), без
   единого расчёта.
2. **`source` и `destination` — оба крипта**: переводить нечего. Если
   указана одна и та же конкретная биржа с обеих сторон — отдельное
   сообщение «уже там»; если биржи разные или не указаны — общее
   пояснение, что перевод между биржами эта версия виджета не считает (нет
   данных о комиссии такого перевода).
3. **валюта источника совпадает с валютой назначения** (оба фиат): то же
   самое — конвертация не нужна.
4. **`destination` — пропфирма, принимающая крипту**: этап биржи (если
   `source` — не крипта) плюс комиссия платёжного провайдера фирмы за
   приём крипты, если она известна (`buildFirmPaymentRow`; сейчас это
   только FTMO — официальные 3%, у остальных помечено как
   `dataVerified: false` и показывается бейдж «не подтверждено»). Колонка
   «получите на руки» заменяется на «дойдёт до фирмы», под таблицей —
   карточка с принимаемыми монетами и прямой ссылкой на сайт фирмы. Если
   `source` не крипта, в качестве этапа покупки перебираются и все `EXCHANGES`
   (6 бирж), и все `OFFRAMPS` с `onRampSupported: true` (обменники) — вторые
   в названии строки помечены суффиксом «(обменник)» и всегда unverified,
   так как тариф на покупку у них отдельно не проверялся (переиспользуется
   подтверждённый тариф на продажу).
5. **`destination` — крипта (не пропфирма), `source` — фиат**:
   только этап биржи/обменника (`buildBuyRow`) — если `destination` —
   конкретная биржа (`crypto:<exchangeId>`), одна строка; если `crypto:all`,
   по одной строке на каждую из `EXCHANGES` плюс на каждый `OFFRAMPS` с
   `onRampSupported: true` (тот же принцип, что в пункте 4 — обменники
   помечены как unverified).
6. **`source` — крипта, `destination` — фиат**: только этап off-ramp
   (`buildOfframpOnlyRow`), без строки биржи и без банка (сравнивать
   банковский перевод не с чем, если деньги уже не в фиате).
7. **оба фиат, валюты разные**: полная матрица — по одной строке на каждую
   пару биржа×off-ramp (`buildRoute`) плюс строка `BANK_BASELINE` для
   контраста.

`FIRMS[].challengePayment` (принимает ли фирма оплату челленджа криптой)
собрано веб-поиском по официальным FAQ фирм 2026-09-12 — см. комментарии
над каждой записью в `data.js`/`data.en.js` для источников.
`cryptoFeePercent: null` там, где сама комиссия платёжного провайдера за
приём крипты не публикуется (FundedNext, The5ers, E8 Markets, BrightFunded,
Blueberry Funded) — виджет честно показывает это как неизвестное, а не
считает комиссию нулевой. У Topstep `acceptsCrypto: false` — единственная
из 7 фирм, которая принимает оплату только банковской картой.

#### Диапазон вместо точного числа у обменников

По ТЗ `calculator-full-rebuild-spec.md` (папка `тех задания сайт/` рядом с
проектом, вне репозитория) — у off-ramp сервисов (Whitebird, Cifra Markets)
нет публичного API тарифов, их курс USDT↔fiat привязан к P2P-рынку и
колеблется, поэтому показывать одно точное число значило бы вводить в
заблуждение ложной точностью. Правило в `calculator.js`: **любой этап, где
участвует обменник** — как off-ramp (`buildOfframpOnlyRow`, `buildRoute`),
так и как альтернатива бирже для покупки (`buildBuyRow`/`buildFirmPaymentRow`
с `isOfframp: true`) — считается диапазоном `finalAmountMin`…`finalAmountMax`
(± `OFFRAMP_TOLERANCE_PERCENT` = 0,4%, середина диапазона «±0,3-0,5%» из ТЗ,
применяется к `spreadPercent` перед расчётом обеих границ). Этап биржи
(`EXCHANGES`) остаётся точным числом — ТЗ прямо говорит, что там колебания
минимальны. `BANK_BASELINE` (контрастный банковский вариант) тоже считается
диапазоном для единообразия — в ТЗ нет отдельных чисел под него, поэтому
используется тот же допуск.

Сортировка результатов — по **нижней границе** диапазона (`finalAmountMin`,
или `finalAmount`, если строка без диапазона), чтобы наверху была самая
консервативная оценка, а не самая оптимистичная. Под таблицей — блок
`rangeDisclaimer` появляется, только если хотя бы одна строка в текущих
результатах помечена `hasRange: true`; если весь маршрут состоит из точных
чисел (например, «карта в USD → конкретная биржа»), блок не показывается.

### Добавление нового языка/страницы

Проще всего скопировать существующую пару файлов (например
`payout/ftmo/index.html` и `en/payout/ftmo/index.html`) и отредактировать
текст — вся логика (калькулятор, курсы, список фирм) подключается через
`<script src="...">` и ничего дублировать в JS не нужно, кроме текстов в
`data.js`/`data.en.js`.

## Что нужно доделать перед запуском

- **Домен**: выберите один из вариантов в разделе 7 ТЗ v1 и подставьте его
  везде, где встречается `LossProof` и `example.com` (заголовки страниц,
  `sitemap.xml`, `robots.txt`).
- **Проверить данные по пропфирмам (вывод)**: на каждой странице фирмы в
  разделе `/payout/` есть красный блок «проверьте», отмечающий неподтверждённые
  цифры (минимальная сумма вывода FundedNext, противоречивые данные по
  комиссии The5ers, скорость E8 Markets) — сверьте их напрямую с фирмой перед
  тем как убирать эти блоки. Записи Topstep, BrightFunded и Blueberry Funded
  в `FIRMS` добавлены веб-поиском 2026-09-08 (источники — в комментарии над
  каждой записью в `data.js`/`data.en.js`) и тоже нужно сверить перед
  запуском — раньше эти три фирмы были только в сравнении (`PROP_FIRMS`) без
  собственной инструкции по выводу.
- **Проверить данные для «Сравнения пропфирм»**: `PROP_FIRMS` в
  `assets/js/data.js` / `data.en.js` собран веб-поиском на дату
  `PROP_FIRMS_RESEARCHED` и НЕ сверялся построчно с официальными сайтами. У
  всех 6 фирм стоит `dataVerified: false`, поэтому на каждой странице
  `/prop-firms/<slug>/` показывается красный блок «сверьте данные». Перед
  публикацией проверьте на официальных сайтах: рейтинг и число отзывов
  Trustpilot, профит-сплит, лимиты просадки, минимальные дни, цены по размерам
  аккаунта (`priceTable`), максимальный размер аккаунта. Особое внимание —
  Topstep (низкий Trustpilot, подписочная модель цены), BrightFunded (молодая
  фирма, рейтинг был скрыт) и Blueberry Funded (мало отзывов). После сверки
  ставьте `dataVerified: true` и убирайте `verify-box` со страницы фирмы.
  Числа в `data.js` и `data.en.js` должны совпадать.
- **Проверить данные для «Сравнения бирж»**: `EXCHANGES_COMPARE` в
  `assets/js/data.js` / `data.en.js` собран веб-поиском на дату
  `EXCHANGES_COMPARE_RESEARCHED` и НЕ сверялся построчно с официальными
  сайтами бирж — у всех 6 стоит `dataVerified: false`, на каждой странице
  `/exchanges/<slug>/` показывается красный блок «сверьте данные». Особое
  внимание — статус `ruAccessTier`/`ruAccessText` (доступ для резидентов РФ):
  это самое изменчивое поле во всей таблице, у Bybit/OKX/Gate прямо
  противоречит их же пользовательскому соглашению. Перепроверяйте перед
  публикацией и периодически после — регулирование в России меняется быстро
  (ожидаются изменения летом 2026). Числа в `data.js` и `data.en.js` должны
  совпадать.
- **Off-ramp данные периодически проверяйте вручную**: спред/комиссии
  Whitebird и Cifra Markets в `assets/js/data.js`/`data.en.js` → `OFFRAMPS`
  взяты с официальных страниц тарифов (ссылки и дата проверки — в
  комментариях над каждым сервисом), а не придуманы. Но ни у одного из этих
  сервисов нет публичного API тарифов, поэтому автообновления нет — раз в
  несколько месяцев стоит вручную свериться по ссылкам и обновить цифры,
  если тариф изменился. Курс валют (в отличие от спреда/комиссий) уже
  обновляется автоматически при каждом расчёте через `rates.js`.
- **Партнёрские ссылки бирж**: в `assets/js/data.js` → `AFFILIATE_LINKS` для
  Bybit, Bitget, KuCoin стоят заглушки `url: null`. После одобрения
  в партнёрке подставьте туда реальные ссылки, и кнопки «Оформить» появятся
  автоматически. Off-ramp сервисы (`OFFRAMPS`) намеренно без ссылок — партнёрки
  там пока не подтверждены. **Важно**: как только появится первая живая
  ссылка, она подпадает под требования закона «О рекламе» РФ о маркировке
  интернет-рекламы (токен `erid` через ОРД, пометка «Реклама», отчётность в
  Роскомнадзор) — сделать это нужно до публикации ссылки, не после.
- **Изображение для соцсетей (OG-картинка)**: пока не добавлено (фавикон уже
  есть, см. ниже).

## Что нужно сделать вручную (не через код)

Это не автоматизируется и не относится к коду сайта. Разобрались, что у
каждого сервиса из ТЗ v2 на самом деле за ситуация с партнёрками:

- **Whitebird, Payeer, AdvCash/Volet** — у всех уже есть открытая
  партнёрская/реферальная программа (0,3% с оборота у Whitebird, до 25% у
  Payeer, 20% у AdvCash/Volet), но получить свою ссылку можно только через
  личный кабинет после регистрации (у Whitebird — ещё и верификация
  личности). Создать аккаунт за вас нельзя — регистрируетесь сами, как и с
  биржами.
- **Cifra Markets** — отдельная форма заявки на партнёрство
  (cifra.by/partners/) для блогеров/контент-сайтов, до 1500₽ за реферала.
  Форма просит ФИО, телефон, email и согласие на обработку персональных
  данных — заполняется вручную.
- **A7A5 — исключён из сайта.** Это не отдельный off-ramp, а рублёвый
  стейблкоин от A7/Old Vector LLC, торгуемый в основном на бирже Grinex.
  Grinex и связанные с A7A5 структуры попали под санкции OFAC Минфина США
  в августе 2025 года как преемник санкционного Garantex — репутационный
  и юридический риск, поэтому убран из `OFFRAMPS` и из всех текстов сайта.
  Не возвращать без повторной проверки санкционного статуса.
- **Подтверждённые партнёрки бирж** (Bybit, Bitget, KuCoin, WhiteBIT) —
  можно подавать заявки уже сейчас, параллельно с доработкой сайта.
